## Intended outcome and starting context

User requested New attendance session in the Next.js app. Session creation previously required the Boost console. Existing server service already constructs the eligible roster with native role, Company, program/group and date/time validations and request-key idempotency.

## Policy decisions and plan

Reuse the existing session service, with online-only creation and permitted program/group choices. Avoid optimistic offline session creation or new business models. Persist the request UUID and scheduling payload in tab storage before sending; recover the same session after uncertain failures/reloads. Keep cancellation/finalization in Boost.

## Work performed

- `attendance_app/app/new-session.js`: responsive native dialog with title, friendly program/group controls, date, start/end times and venue. Uses academy timezone/default date, filters groups by selected program and resets incompatible selection. Validates end after start on the same day.
- Creation uses existing authenticated configuration/create_session APIs and current account/company/CSRF preflight. Successful creation refreshes the session list and opens/downloads its roster on a trusted device. Untrusted devices receive the created reference and can enable trusted mode separately.
- Stable request stored per user/company in sessionStorage. Uncertain outcome locks values for same-request retry; reload and reopening New session restores it. Known validation failures allow correction. Closing retains the uncertain request; successful creation clears it. No offline creation.
- `attendance_api.configuration`: advisory can_create requires native create permission for both Sports Session and Sports Attendance. No role grants or replacement for server insert checks.
- `attendance_app/app/api.js`: expose HTTP status to distinguish validation failures from uncertain outcomes. Existing attendance sync behavior unchanged.
- Updated usage guide, frontend README, requirements/PRD and story acceptance refinement. Prior console-only creation scope is superseded; original logs preserved.
